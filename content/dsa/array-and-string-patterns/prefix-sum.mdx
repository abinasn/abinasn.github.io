## Definition

A **prefix sum** array stores running totals: cell `i` holds the sum of the first `i` values of the original array. Once it is built, the sum of any **range** (a run of consecutive positions, `left` to `right` inclusive) takes one subtraction.

```
arr:      3   1   4   1   5   9
prefix:   0   3   4   8   9  14  23
```

## The problem it solves

Many range-sum questions asked about the same array:

```
arr index:   0   1   2   3   4   5
arr:         3   1   4   1   5   9
```

| Question | Values added | Additions |
|---|---|---|
| sum of 1..3 | 1 + 4 + 1 | 3 |
| sum of 2..5 | 4 + 1 + 5 + 9 | 4 |
| sum of 0..4 | 3 + 1 + 4 + 1 + 5 | 5 |

The direct approach loops over each range, so `4` and `1` are added again in every question. With 100,000 values and 100,000 questions, each up to the full length, that is up to 10¹⁰ additions.

## How it works

### 1. Running totals

Add once, left to right, writing down the total so far:

| idx | 0 | 1 | 2 | 3 | 4 | 5 |
|---|---|---|---|---|---|---|
| arr | 3 | 1 | 4 | 1 | 5 | 9 |
| running | 3 | 4 | 8 | 9 | 14 | 23 |

Each cell is built from the one before it: `running[i] = running[i − 1] + arr[i]`. For example, `running[3] = 9` is everything from idx 0 up to and including idx 3.

### 2. A range as one subtraction

Sum of idx 2..4:

```
idx:          0   1 | 2   3   4
arr:          3   1 | 4   1   5

running[4] =  3 + 1 + 4 + 1 + 5   = 14   everything up to idx 4
running[1] =  3 + 1               =  4   everything before idx 2
              ───── cancels
difference =          4 + 1 + 5   = 10   only idx 2..4
```

The total up to `right` contains an unwanted part: everything before `left`. That part is exactly another stored total, so subtracting it leaves the range.

```
sum(left..right) = running[right] − running[left − 1]
```

### 3. The crack at index 0

A range starting at idx 0 needs `running[−1]`:

```
sum(0..3) = running[3] − running[−1]
          = 9 − undefined
          = NaN
```

The value that belongs there is the sum of nothing before idx 0, which is **0**. An `if (left === 0)` branch can supply it, but the formula then has a special case.

### 4. The padded array

Put a `0` at the front. Every total shifts one slot right, and the array has length **n + 1**:

```
arr index:        0   1   2   3   4   5
arr:              3   1   4   1   5   9
                   ↘   ↘   ↘   ↘   ↘   ↘
prefix:       0   3   4   8   9  14  23
prefix index: 0   1   2   3   4   5   6
```

| Cell | Built as | Adds up |
|---|---|---|
| `prefix[0]` = 0 | start | nothing |
| `prefix[1]` = 3 | 0 + `arr[0]` | first 1 value |
| `prefix[2]` = 4 | 3 + `arr[1]` | first 2 values |
| `prefix[4]` = 9 | 8 + `arr[3]` | first 4 values |
| `prefix[6]` = 23 | 14 + `arr[5]` | all 6 values |

`prefix[i]` now means **the sum of the first `i` values**. "Up to and including idx r" is the first r + 1 values, because idx 0 is the first value.

Re-deriving the range formula in those words:

| Range | Up to `right` | Before `left` | Result |
|---|---|---|---|
| 2..4 | first 5 values: `prefix[5]` = 14 | first 2 values: `prefix[2]` = 4 | 10 |
| 0..3 | first 4 values: `prefix[4]` = 9 | first 0 values: `prefix[0]` = 0 | 9 |
| 5..5 | first 6 values: `prefix[6]` = 23 | first 5 values: `prefix[5]` = 14 | 9 = `arr[5]` |

```
sum(left..right) = prefix[right + 1] − prefix[left]
```

The range starting at idx 0 now reads `prefix[0]`, which exists, so no branch is needed.

## The invariant

After the build, `prefix[i]` equals the sum of `arr[0..i−1]` for every `i` from 0 to n, with `prefix[0] = 0`. A range sum is therefore always the difference of two stored cells.

## Implementation

```js
// Build once: prefix[i] = sum of the first i values (arr[0..i-1])
function buildPrefix(arr) {
  const prefix = new Array(arr.length + 1).fill(0); // prefix[0] = 0: sum of nothing
  for (let i = 0; i < arr.length; i++) {
    prefix[i + 1] = prefix[i] + arr[i];
  }
  return prefix;
}

// Sum of arr[left..right], inclusive
function rangeSum(prefix, left, right) {
  // first right+1 values minus first left values
  return prefix[right + 1] - prefix[left];
}

const prefix = buildPrefix([3, 1, 4, 1, 5, 9]); // [0, 3, 4, 8, 9, 14, 23]
rangeSum(prefix, 2, 4); // 14 - 4 = 10
rangeSum(prefix, 0, 3); //  9 - 0 = 9
```

## Complexity

| Approach | Build | Per query | Space | Why |
|---|---|---|---|---|
| Loop over each range | none | O(n) | O(1) | re-adds every value in the range |
| Prefix sums | O(n) | O(1) | O(n) | each value added once; a query reads two cells |

For q queries, the totals are O(n · q) against O(n + q).

## Edge cases

| Case | What breaks | How the padded array handles it |
|---|---|---|
| Range starts at idx 0 | unpadded formula reads index −1 → `NaN` | reads `prefix[0] = 0` |
| Range of one value | none | `prefix[i + 1] − prefix[i] = arr[i]` |
| Negative values | none | subtraction cancels the unwanted part whatever its sign |
| Array changes after the build | stored totals go stale | not handled: the array must stay fixed |
| Off-by-one on the padded array | `prefix[right] − prefix[left − 1]` returns the range shifted one left | use `right + 1` and `left` |

## Variant: prefix and suffix products

The same idea works for any operation that has a **"nothing yet" value**, the value that leaves its partner unchanged.

| Operation | Pad with | Because |
|---|---|---|
| Sum | 0 | x + 0 = x |
| Product | 1 | x × 1 = x |

A **suffix** array is a prefix array built from the right: `suffix[j]` holds the combination of `arr[j..end]`. Together they give "everything except index i":

```
everything except i  =  (everything left of i)  ×  (everything right of i)
                     =        prefix[i]         ×      suffix[i + 1]
```

Products cannot use the subtract-to-cancel trick. Undoing a product means dividing, and a single 0 makes division impossible. Splitting into a left part and a right part avoids undoing anything.

## When to use / avoid

**Use when:**
- the same array is asked many range-sum questions
- a value is needed "for everything before i" or "for everything after i"
- the array does not change between questions

**Avoid when:**
- there is only one range question: a single loop is just as fast and needs no extra array
- values change between questions: every update would rebuild the totals

<Solution problem="303. Range Sum Query - Immutable">

**Approach.** The constructor builds the padded prefix array once and keeps it on the instance. Each `sumRange` call returns `prefix[right + 1] − prefix[left]`.

**Invariant.** `this.prefix[i]` is the sum of `nums[0..i−1]`, and it never changes after construction.

```js
var NumArray = function (nums) {
  this.prefix = new Array(nums.length + 1).fill(0); // prefix[0] = 0
  for (let i = 0; i < nums.length; i++) {
    this.prefix[i + 1] = this.prefix[i] + nums[i];  // sum of first i+1 values
  }
};

NumArray.prototype.sumRange = function (left, right) {
  return this.prefix[right + 1] - this.prefix[left]; // one subtraction
};
```

Hand trace: `nums = [-2, 0, 3, -5, 2, -1]`

```
nums index:     0   1   2   3   4   5
nums:          -2   0   3  -5   2  -1
prefix:     0  -2  -2   1  -4  -2  -3
```

| Call | Cells | Result |
|---|---|---|
| `sumRange(0, 2)` | `prefix[3] − prefix[0]` = 1 − 0 | 1 |
| `sumRange(2, 5)` | `prefix[6] − prefix[2]` = −3 − (−2) | −1 |
| `sumRange(0, 5)` | `prefix[6] − prefix[0]` = −3 − 0 | −3 |

**Cost.** O(n) time and O(n) space to build; O(1) per call.

<Solution problem="238. Product of Array Except Self">

**Approach.** Build a prefix product array padded with 1 from the left and a suffix product array padded with 1 from the right. The answer at `i` is the product of everything left of `i` times everything right of `i`.

**Invariant.** `prefix[i]` is the product of `nums[0..i−1]` and `suffix[j]` is the product of `nums[j..n−1]`, with both empty products equal to 1.

```js
var productExceptSelf = function (nums) {
  const n = nums.length;
  const prefix = new Array(n + 1).fill(1); // prefix[0] = 1: product of nothing
  const suffix = new Array(n + 1).fill(1); // suffix[n] = 1: product of nothing

  for (let i = 0; i < n; i++) {
    prefix[i + 1] = prefix[i] * nums[i];   // product of first i+1 values
  }
  for (let j = n - 1; j >= 0; j--) {
    suffix[j] = suffix[j + 1] * nums[j];   // product of nums[j..n-1]
  }

  const answer = new Array(n);
  for (let i = 0; i < n; i++) {
    answer[i] = prefix[i] * suffix[i + 1]; // left of i × right of i
  }
  return answer;
};
```

Hand trace: `nums = [1, 2, 3, 4]`

```
nums index:     0   1   2   3
nums:           1   2   3   4
prefix:     1   1   2   6  24
suffix:        24  24  12   4   1
```

| i | Left: `prefix[i]` | Right: `suffix[i + 1]` | Answer |
|---|---|---|---|
| 0 | 1 | 24 | 24 |
| 1 | 1 | 12 | 12 |
| 2 | 2 | 4 | 8 |
| 3 | 6 | 1 | 6 |

The padding handles both ends: index 0 has nothing on its left (1), and index 3 has nothing on its right (1).

**Cost.** O(n) time; O(n) extra space for the two arrays. Writing the prefix products straight into the answer array and folding the suffix into a single running variable brings the extra space down to O(1), not counting the output.

</Solution>

## TL;DR

- A prefix array stores running totals once: `prefix[i]` is the sum of the first `i` values.
- Any range sum is one subtraction: `prefix[right + 1] − prefix[left]`, because the total up to `right` minus the total before `left` cancels everything outside the range.
- Padding with a leading 0, the sum of nothing, removes the index-0 special case.
- Build O(n) once, then O(1) per query, for an array that does not change.
- The same idea works for products padded with 1; pair a prefix with a suffix to get "everything except i".
