## Definition

**Sorting plus two pointers** is a technique for finding every group of k values in an array that adds up to a target. The array is sorted first, loops fix all but two of the values, and a two-pointer scan finds the last two.

The general task is called **k-sum**. 3-sum looks for triplets (groups of three), and 4-sum looks for quadruplets (groups of four).

```
index:     0    1    2    3    4    5
value:    -4   -1   -1    0    1    2
                a    L              R
              fixed  └─── scan ─────┘
```

## The problem it solves

The task used throughout: find every **unique** triplet of values that sums to 0. Unique means by value, so `[-1, 0, 1]` and `[0, 1, -1]` are the same answer.

The strawman, the approach being replaced, tries every choice of three positions `p < q < r` with three nested loops. Counting its checks by hand for `[-1, 0, 1, 2, -1, -4]` (n = 6):

| `p` | `q` choices, with `r` choices each | Checks |
| --- | --- | --- |
| 0 | q=1→4, q=2→3, q=3→2, q=4→1 | 10 |
| 1 | q=2→3, q=3→2, q=4→1 | 6 |
| 2 | q=3→2, q=4→1 | 3 |
| 3 | q=4→1 | 1 |
| | **Total** | **20** |

Three nested loops over n values grow as **O(n³)**. The strawman also reports the same answer twice:

| Positions | Values | Sum |
| --- | --- | --- |
| 0, 1, 2 | `-1, 0, 1` | 0 |
| 0, 3, 4 | `-1, 2, -1` | 0 |
| 1, 2, 4 | `0, 1, -1` | 0, the same values as row 1 |

Removing the repeats would mean sorting each triplet and storing it in a `Set`, on top of the O(n³) search.

## How it works

### 1. The two-pointer scan on sorted values

On a sorted array, a pair with a given sum can be found with index `L` at the start and index `R` at the end. If the pair's sum is too big, `R` moves left; if it is too small, `L` moves right; if it is equal, the pair is found.

Hand trace: `[1, 3, 4, 6, 8, 11]`, target 10:

| `nums[L]` | `nums[R]` | Sum | Move | Why the dropped value is useless |
| --- | --- | --- | --- | --- |
| 1 | 11 | 12 | `R--`, drop 11 | 11 plus the smallest value left already overshoots |
| 1 | 8 | 9 | `L++`, drop 1 | 1 plus the largest value left still falls short |
| 3 | 8 | 11 | `R--`, drop 8 | 8 plus the smallest value left overshoots |
| 3 | 6 | 9 | `L++`, drop 3 | 3 plus the largest value left falls short |
| 4 | 6 | 10 | found | — |

Each step throws out one value that provably cannot be part of an answer. So a scan over m values takes at most m − 1 steps.

### 2. The reduction: fix one, scan for two

For a triplet `a + b + c = 0`, fix `a = nums[i]`. What remains is `b + c = −a`, which is a pair search, solved by the scan above on the values to the right of `i`.

Hand trace: sorted `[-4, -1, -1, 0, 1, 2]`, one round per fixed `a`:

| `i` | `a` | Need `b + c` | Scanned range | Found |
| --- | --- | --- | --- | --- |
| 0 | -4 | 4 | `[-1, -1, 0, 1, 2]` | — |
| 1 | -1 | 1 | `[-1, 0, 1, 2]` | `[-1, -1, 2]`, `[-1, 0, 1]` |
| 2 | -1 | 1 | `[0, 1, 2]` | `[-1, 0, 1]`, a repeat |
| 3 | 0 | 0 | `[1, 2]` | — |

- The scan only looks **right** of `i`. Every triplet has a leftmost member, and the round where that member is `a` finds it, so looking left would redo finished rounds.
- `L` starts at `i + 1`, so `a` is never reused as `b`.
- `L` and `R` restart every round, because each `a` is a new pair search on a new range.
- The repeat in round 2 is removed in step 4.

### 3. What sorting buys

Sorting provides two separate things:

| Property | Unsorted array | Sorted array |
| --- | --- | --- |
| Direction | A sum that is too big says nothing about which value to drop | Too big: drop the largest (`R--`). Too small: drop the smallest (`L++`) |
| Repeats | Spotting a repeat needs a `Set` of every value seen | Equal values sit side by side, so one look at the neighbour is enough |

The cost is that original positions are lost. That is fine when the answer is values, not positions.

Sort numerically in JavaScript with `nums.sort((a, b) => a - b)`. The default `sort()` compares values as strings, so `[-1, 0, 1, 2, -1, -4].sort()` gives `[-1, -1, -4, 0, 1, 2]`.

### 4. Skipping repeats

Repeats enter at two places: the fixed value `a`, and the pair `b, c`. Each gets its own skip.

**Skip 1, at `a`: skip a value equal to the one before it.** In the step 2 trace, round `i = 2` has `a = -1`, the same as `nums[1]`, so it is skipped and the repeat disappears.

Comparing with the value **after** instead loses an answer:

| `i` | `a` | Value after | Action |
| --- | --- | --- | --- |
| 1 | -1 | -1 | skip |
| 2 | -1 | 0 | run, scans `[0, 1, 2]`, finds only `[-1, 0, 1]` |

`[-1, -1, 2]` is lost, because the second `-1` has no `-1` to its right. The first copy of a value scans the widest range, including its own twins, so it finds everything a later copy could.

**Skip 2, at `b, c`: after a match, move past equal values.**

Hand trace: `[-2, 0, 0, 2, 2]` with `a = -2`, so `b + c` must be 2.

Without the skip:

| `L` | `R` | `a + b + c` | Action |
| --- | --- | --- | --- |
| 1 | 4 | 0 | record `[-2, 0, 2]`; `L = 2`, `R = 3` |
| 2 | 3 | 0 | record `[-2, 0, 2]` again |

With the skip:

| `L` | `R` | `a + b + c` | Action |
| --- | --- | --- | --- |
| 1 | 4 | 0 | record `[-2, 0, 2]`; `L = 2`, `R = 3` |
| 2 | 3 | — | `nums[2]` equals the `b` just recorded, so `L = 3`; now `L = R` and the scan ends |

A non-match needs no skip. The moving index is dropping a value proven useless, and its copies are dropped the same way, one step at a time; the skip only stops the same answer being **recorded** twice.

### 5. Generalising to k-sum

Each fixed value peels off one layer, and the two-pointer scan is always the bottom layer.

| Task | Fixed by loops | Scan for |
| --- | --- | --- |
| 2-sum | nothing | `b + c = target` |
| 3-sum | `a` | `b + c = target − a` |
| 4-sum | `a`, then `b` | `c + d = target − a − b` |
| k-sum | k − 2 values | the last two |

Skip 1 applies at every fixed layer, with one rule: **a layer's first candidate is never skipped**, because the value before it belongs to the layer above.

Hand trace: 4-sum on `[2, 2, 2, 2]`, target 8. With `a` at index 0, `b` starts at index 1:

| Skip check for `b` | Result |
| --- | --- |
| Compare index 1 with index 0 | Equal, so `b` is skipped and the only answer `[2, 2, 2, 2]` is lost |
| Compare only from index `i + 2` onward | Index 1 runs and the answer is found |

So the `a` layer checks from index 1, and the `b` layer checks from index `i + 2`.

## The invariant

For fixed outer values, at every step of the scan:

> Every pair not yet examined lies inside `nums[L..R]`; every pair with a member outside that range has already been recorded or ruled out.

- The scan ends when `L` meets `R`. The unexamined range is then empty, so no answer was missed.
- Every branch shrinks the gap: a sum that is too big moves `R`, too small moves `L`, and a match moves both. So the scan always ends.
- `L === R` stops the scan, because one slot cannot be both `b` and `c`.
- The skips add a second guarantee: each distinct value fills each position at most once, so no answer is recorded twice.

## Implementation

The scan is the bottom layer shared by every k. Each fixed value adds one loop around it.

```js
// nums must be sorted ascending.
// Appends [...fixed, b, c] for every unique pair with b + c === target in nums[start..].
function scanPairs(nums, start, target, fixed, out) {
  let L = start, R = nums.length - 1;
  while (L < R) {
    // invariant: every unexamined pair lies in nums[L..R]
    const sum = nums[L] + nums[R];
    if (sum > target) R--;          // nums[R] overshoots even with the smallest partner
    else if (sum < target) L++;     // nums[L] falls short even with the largest partner
    else {
      out.push([...fixed, nums[L], nums[R]]);
      L++; R--;
      while (L < R && nums[L] === nums[L - 1]) L++;   // move past copies of b
      while (L < R && nums[R] === nums[R + 1]) R--;   // move past copies of c
    }
  }
}

// One fixed layer on top: 3-sum for any target.
function threeSumTarget(nums, target) {
  nums.sort((x, y) => x - y);                        // numeric, not string, order
  const out = [];
  for (let i = 0; i < nums.length - 2; i++) {
    if (i > 0 && nums[i] === nums[i - 1]) continue;  // same a as the round before
    scanPairs(nums, i + 1, target - nums[i], [nums[i]], out);
  }
  return out;
}

threeSumTarget([-1, 0, 1, 2, -1, -4], 0);  // [[-1, -1, 2], [-1, 0, 1]]
```

## Complexity

Count the scan steps for the array in step 2. A fixed `a` with m values to its right needs at most m − 1 steps:

| Fixed `a` at | Values to its right | Max steps |
| --- | --- | --- |
| index 0 | 5 | 4 |
| index 1 | 4 | 3 |
| index 2 | 3 | 2 |
| index 3 | 2 | 1 |
| | **Total** | **10** |

`4 + 3 + 2 + 1` is the same shrinking sum that two nested loops produce, so it grows as **O(n²)**. The gap to the strawman widens quickly:

| n | Strawman checks | Scan steps, at most |
| --- | --- | --- |
| 6 | 20 | 10 |
| 100 | 161,700 | 4,851 |
| 1,000 | 166,167,000 | 498,501 |

| Task | Time | Extra space | Why |
| --- | --- | --- | --- |
| 3-sum, strawman | O(n³) | O(1) | Three nested loops |
| 3-sum, sort + scan | O(n²) | O(1) | n fixed values, each followed by a scan of at most n steps |
| 4-sum, sort + scan | O(n³) | O(1) | Two fixed layers around one scan |
| k-sum, sort + scan | O(nᵏ⁻¹) | O(1) | k − 2 fixed layers around one scan |

The sort runs once, before any scan, and the built-in sort costs O(n log n). For k ≥ 3 that grows more slowly than the scans, so the scans dominate. Extra space excludes the output list and any memory the sort uses internally.

## Edge cases

| Case | What breaks | How the code handles it |
| --- | --- | --- |
| Default `sort()` | Sorts as strings: `[-1, 0, 1, 2, -1, -4]` becomes `[-1, -1, -4, 0, 1, 2]`, so the scan moves the wrong way | Sort with `(a, b) => a - b` |
| All values equal: `[0, 0, 0, 0]` | Without skips, `[0, 0, 0]` is recorded more than once | Both skips together leave one answer |
| A layer's first candidate equals the value above it: `[2, 2, 2, 2]`, target 8 | Skipping it loses the only answer | The `b` skip check runs only when `j > i + 1` |
| Stopping once `nums[i] > target` | Safe for target 0, where every later value is positive too; wrong for a negative target: 4-sum of `[-3, -2, -1, -1]`, target −7 | Stop early on `nums[i] > 0` only when the target is 0 |

## When to use

- Every group of k values (k ≥ 3) with an exact target sum is required.
- The answer is values, and a repeated answer must be reported once.
- The array may be rearranged, or copied and then sorted.

## When to avoid

- The answer must be original positions: sorting moves values, and the positions are lost.
- The array must keep its original order and a copy is not allowed.
- k is large: time grows as nᵏ⁻¹, one factor of n for each extra value.

<Solution problem="15. 3Sum">

**Approach.** Sort numerically, fix `a = nums[i]`, and scan `nums[i+1..]` for pairs that bring the sum to 0. The code compares the full sum `a + b + c` with 0, which is the same test as comparing `b + c` with `−a`. Once `a` is positive, every later value is positive too, so no triplet can reach 0 and the loop stops.

**Invariant.** For the current `a`, every unexamined pair lies in `nums[L..R]`, and each distinct value fills each position at most once.

```js
var threeSum = function (nums) {
  nums.sort((a, b) => a - b);                        // numeric order
  const result = [];
  for (let i = 0; i < nums.length - 2; i++) {
    if (i > 0 && nums[i] === nums[i - 1]) continue;  // same a as the round before
    if (nums[i] > 0) break;                          // only positives remain; valid because the target is 0
    let L = i + 1, R = nums.length - 1;              // fresh scan for every a
    while (L < R) {
      const sum = nums[i] + nums[L] + nums[R];
      if (sum > 0) R--;
      else if (sum < 0) L++;
      else {
        result.push([nums[i], nums[L], nums[R]]);
        L++; R--;
        while (L < R && nums[L] === nums[L - 1]) L++;  // past copies of b
        while (L < R && nums[R] === nums[R + 1]) R--;  // past copies of c
      }
    }
  }
  return result;
};
```

Hand trace for `[-1, 0, 1, 2, -1, -4]`, sorted to `[-4, -1, -1, 0, 1, 2]`:

| `i` | `a` | `L` | `R` | Sum | Action |
| --- | --- | --- | --- | --- | --- |
| 0 | -4 | 1 | 5 | -3 | `L++` |
| 0 | -4 | 2 | 5 | -3 | `L++` |
| 0 | -4 | 3 | 5 | -2 | `L++` |
| 0 | -4 | 4 | 5 | -1 | `L++`; now `L = R`, round ends |
| 1 | -1 | 2 | 5 | 0 | record `[-1, -1, 2]`; `L = 3`, `R = 4` |
| 1 | -1 | 3 | 4 | 0 | record `[-1, 0, 1]`; `L = 4`, `R = 3`, round ends |
| 2 | -1 | — | — | — | skip: equals `nums[1]` |
| 3 | 0 | 4 | 5 | 3 | `R--`; now `L = R`, round ends |

Returns `[[-1, -1, 2], [-1, 0, 1]]`.

**Cost.** Time O(n²), extra space O(1) beyond the output and the sort.

<Solution problem="18. 4Sum">

**Approach.** Two fixed layers, `a = nums[i]` and `b = nums[j]` with `j > i`, then a scan of `nums[j+1..]` for `c + d = target − a − b`. Each layer skips a value equal to the one before it, starting from its own second candidate. The early stop from 3-sum is left out, because with a negative target a value larger than the target can still belong to an answer.

**Invariant.** For the current `a` and `b`, every unexamined pair lies in `nums[L..R]`, and each distinct value fills each position at most once.

```js
var fourSum = function (nums, target) {
  nums.sort((a, b) => a - b);
  const result = [];
  const n = nums.length;
  for (let i = 0; i < n - 3; i++) {
    if (i > 0 && nums[i] === nums[i - 1]) continue;        // a layer: first candidate is i = 0
    for (let j = i + 1; j < n - 2; j++) {
      if (j > i + 1 && nums[j] === nums[j - 1]) continue;  // b layer: first candidate is j = i + 1
      let L = j + 1, R = n - 1;
      while (L < R) {
        const sum = nums[i] + nums[j] + nums[L] + nums[R];
        if (sum > target) R--;
        else if (sum < target) L++;
        else {
          result.push([nums[i], nums[j], nums[L], nums[R]]);
          L++; R--;
          while (L < R && nums[L] === nums[L - 1]) L++;    // past copies of c
          while (L < R && nums[R] === nums[R + 1]) R--;    // past copies of d
        }
      }
    }
  }
  return result;
};
```

Hand trace for `[1, 0, -1, 0, -2, 2]`, target 0, sorted to `[-2, -1, 0, 0, 1, 2]`:

| `i` | `a` | `j` | `b` | Need `c + d` | Scanned range | Found |
| --- | --- | --- | --- | --- | --- | --- |
| 0 | -2 | 1 | -1 | 3 | `[0, 0, 1, 2]` | `[-2, -1, 1, 2]` |
| 0 | -2 | 2 | 0 | 2 | `[0, 1, 2]` | `[-2, 0, 0, 2]` |
| 0 | -2 | 3 | 0 | — | — | skip: equals `nums[2]` |
| 1 | -1 | 2 | 0 | 1 | `[0, 1, 2]` | `[-1, 0, 0, 1]` |
| 1 | -1 | 3 | 0 | — | — | skip: equals `nums[2]` |
| 2 | 0 | 3 | 0 | 0 | `[1, 2]` | — |

In the last row, `nums[3]` equals `nums[2]`, but `j = 3` is the `b` layer's first candidate in round `i = 2`, so it runs.

Values in this problem reach 10⁹, so four of them can sum to about 4 × 10⁹. JavaScript numbers hold integers exactly up to 2⁵³, so the sum is safe, while a 32-bit integer type would overflow.

**Cost.** Time O(n³), extra space O(1) beyond the output and the sort.

</Solution>

## TL;DR

- Sort numerically, fix k − 2 values with loops, and find the last two with a two-pointer scan from both ends.
- Sorting gives direction (too big: move `R` left; too small: move `L` right) and puts equal values side by side.
- Skip a fixed value equal to the one before it, but never a layer's first candidate; after a match, move `L` and `R` past copies.
- Invariant: every unexamined pair lies between `L` and `R`, and everything outside has been recorded or ruled out.
- 3-sum drops from O(n³) to O(n²); each extra fixed value multiplies the time by n.
