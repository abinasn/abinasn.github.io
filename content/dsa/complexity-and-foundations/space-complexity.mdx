## Definition

**Space complexity** measures how much extra memory an algorithm needs, beyond the input itself, as the input size grows. It is written the same way as time complexity, using Big-O, but it counts memory instead of operations.

That memory comes from two separate places: **auxiliary space**, the extra data structures a program creates, and **call stack space**, the memory used by function calls that have started but not yet finished. Total space complexity is the sum of both.

## How it works

### Auxiliary space: the survival test

Not every variable adds to space complexity — only the ones still alive at the point memory usage peaks. A value is **live** if something can still read it; once nothing can reach it anymore, it stops counting.

```js
function sumArray(arr) {
  let total = 0;
  for (const x of arr) {
    total += x; // total is overwritten, not grown
  }
  return total;
}

function hasDuplicate(arr) {
  const seen = new Set();
  for (const x of arr) {
    if (seen.has(x)) return true;
    seen.add(x); // seen keeps growing
  }
  return false;
}
```

Hand trace with `arr = [3, 1, 4, 1]`:

| iteration | `total` (sumArray) | `seen` (hasDuplicate) |
|---|---|---|
| 1 | 3 | `{3}` |
| 2 | 4 | `{3, 1}` |
| 3 | 8 | `{3, 1, 4}` |
| 4 | 9 | duplicate found, returns |

`total` holds one number the whole time — each iteration overwrites it. `seen` keeps every value ever added to it; nothing is removed. The test: **does this iteration's data survive into the next one, or does it die with the iteration?**

`total` dies and is replaced each time, so `sumArray` uses O(1) auxiliary space. `seen` survives and accumulates, so `hasDuplicate` uses O(n) auxiliary space — in the worst case, no duplicate exists and `seen` ends up holding all `n` elements.

### Call stack space: frames that wait

A function call costs memory even if it creates no variables of its own. Calling a function allocates a **stack frame**, a block holding its parameters, its local variables, and where execution should resume once it returns. The frame exists from the moment the call starts to the moment it returns.

Frames stack on top of each other only when one call is still waiting on another. Trace `countdown`:

```js
function countdown(n) {
  if (n === 0) return;
  countdown(n - 1); // waits for the inner call to return
}
```

Stack height while running `countdown(3)`:

```
countdown(3) called    → [3]
  countdown(2) called  → [3, 2]
    countdown(1) called→ [3, 2, 1]
      countdown(0)     → [3, 2, 1, 0]   ← peak: 4 frames
      returns           → [3, 2, 1]
    returns              → [3, 2]
  returns                → [3]
returns                  → []
```

Peak height is 4, one frame per call, because each call waits for the next one before it can return. For `countdown(n)`, peak height is `n + 1`; the dominant term is `n`, so call stack space is O(n).

Compare that with calls that run one after another instead of nested inside each other:

```js
function runBoth() {
  first();  // called, finishes, frame removed
  second(); // called only after first() is already gone
}
```

`first`'s frame is gone before `second`'s frame appears, so they never coexist. Peak height here is 2, not 3, because nothing is nested.

## The invariant

At any instant, only *live* memory counts toward the total: a value that has been created but not yet released, or a stack frame belonging to a call that has started but not yet returned. Anything already released — a discarded local variable, or a frame that has popped off the stack — never adds to the count again.

## Implementation

```js
// Auxiliary space: O(n) — `seen` grows with the input
function hasDuplicate(arr) {
  const seen = new Set();
  for (const x of arr) {
    if (seen.has(x)) return true;
    seen.add(x);
  }
  return false;
}

// Call stack space: O(n) — one frame per call, n deep
function sumRecursive(arr, i = 0) {
  if (i === arr.length) return 0;
  return arr[i] + sumRecursive(arr, i + 1); // waits for the recursive call
}
```

## Key terms

| Term | Meaning |
|---|---|
| Auxiliary space | Extra memory a program allocates beyond the input itself |
| Total space complexity | Auxiliary space plus call stack space, combined |
| Stack frame | A block of memory holding one function call's parameters, local variables, and return address |
| Call stack | The stack of frames belonging to calls that have started but not yet returned |
| Recursion depth | The peak number of frames a recursive function creates before any of them return |
| Live | Still reachable — something in the program can still read this value |

## Edge cases

| Case | What breaks | How it's handled |
|---|---|---|
| Recursion with no base case, or a base case that's never reached | Frames keep getting pushed and none ever pop | JavaScript throws `RangeError: Maximum call stack size exceeded` once the stack's memory limit is hit |

## When to use / avoid

Recognize O(1) auxiliary space when:
- A fixed number of variables are reused across iterations, not stored in a growing collection.
- Values are overwritten in place rather than appended anywhere.

Recognize growing space when:
- A structure such as a `Set`, `Map`, or array is built up across the whole loop and never shrinks.
- A function calls itself and each call waits for the next to return — depth grows with input size.

## TL;DR

- Space complexity measures extra memory beyond the input, written in Big-O like time complexity.
- It has two parts: auxiliary space (data structures created) and call stack space (frames from calls that haven't returned).
- The survival test for auxiliary space: does this iteration's data outlive the iteration, or die with it? Surviving data accumulates; dying data doesn't.
- A stack frame exists from a call's start to its return; frames stack on top of each other only when one call is nested inside — waiting on — another.
- Peak frame count, not total number of calls made, determines call stack space.
- Total space complexity = auxiliary space + call stack space.
